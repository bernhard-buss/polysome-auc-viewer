Help

A typical session

  1. Load the single-trace instrument exports (one CSV per sample). Add an empty-gradient run if you have one and select it as Blank gradient. Returning to an analysis? Load session first, then the same files.
  2. Check the landmark line under the chart: 40S / 60S / 80S positions, valleys g1–g4, and the pure-offset verdict. If a sample's valleys deviate, its QC flag tells you.
  3. Auto-set boundaries (done automatically on load; press the button again after adding or hiding samples). Drag the lines only if the rule puts one somewhere obviously wrong — and then keep it there for every sample.
  4. Tick remove spikes; keep the flat — minimum baseline unless you loaded a blank.
  5. Fill in block, group and (if recorded) loaded A260 per sample, type the contrasts you planned, then Lock settings.
  6. Read the results table together with its QC column and the sensitivity range; export the tidy table for statistics and Save session for the notebook.
Decide metric, baseline, boundary rule and exclusion criteria before looking at the ratios. The lock stamps a settings hash on every export so later changes are visible.

What happens to each trace, in order

  1. Blank subtraction (optional): the blank's OD, interpolated on the sample's raw positions, is subtracted first.
  2. Spike repair: bubbles are 1–3-sample excursions > 10 robust σ from a ±0.3 mm running median (σ from the median absolute first difference, floor 0.003 OD). They are always flagged; with remove spikes on they are replaced by the local median.
  3. Smoothing: Savitzky-Golay, 1.5 mm window, cubic — used only to find peaks and valleys. Integration always uses the unsmoothed data.
  4. Landmarks: the very first (free-RNA) peak and its onset (trace drops below 5 % of the apex); the 80S = most prominent peak in 22–42 mm; 60S and 40S walking left in 4–9.5 mm steps; polysome peaks to the right. Peaks need prominence ≥ max(0.003 OD, 6σ) and ≥ 1.2 mm separation.
  5. Alignment: every trace is shifted so its 80S sits at 32.0 mm (the reference is fixed, so windows are portable between sessions).
  6. Consensus: medians of the aligned valleys over the loaded samples; the common endpoint is the shortest coverage − 0.5 mm.

Total AUC starts at the onset of the very first data peak, so it includes the free-RNA peak and excludes only the start artefacts before it.

Gradient profile (advanced)

The landmark search assumes a geometry: where the void ends, where the 80S can be, how far apart the subunit peaks sit, where to look for g4, and the aligned 80S reference. The defaults are for 10–50 % sucrose in an SW41 tube. For a different gradient, adjust them in the Gradient profile group (the preset switches to “custom”); the profile is part of the settings hash and of every export. A QC flag warns when a peak outside the 80S window is more prominent than the chosen 80S — the usual symptom of a wrong window.

Shift + scale (advanced)

Runs from one spin share ω²t, but gradient shape (gradient-maker variation, fill volume, diffusion while waiting) can compress or stretch the position scale by a few percent. The optional shift + scale mode fits x = a + b·xref per sample by least squares on landmarks of known identity (40S, 60S, 80S, disome, trisome) against their shift-only consensus. Rules that keep this honest: linear only (never elastic warping); small factors only — |b − 1| beyond 5 % is flagged as a physically different gradient to exclude rather than correct; b is reported per sample (under the x-shift, and in the exports); and areas are integrated in each sample's native mm, so no area is multiplied by b. Because a uniform stretch scales both regions equally, Poly/Mono is invariant to it — the mode only makes shared boundaries land more consistently. Keep shift-only unless the landmark line or the sensitivity range shows a scale problem.

Pure-offset test

If every sample's g1–g3 valleys sit within 1.5 mm of the consensus after alignment, the x-shifts are a pure meniscus-detection offset and the gradients are physically equivalent. A larger deviation means that gradient differs in scale; a single shift cannot align it, and the sample is flagged.

Polysome ladder (2-, 3-, 4-, 5-mer)

Polysome peaks are small (a few mOD on a rising hump), so they are searched with a relaxed threshold — peaks with prominence ≥ max(0.0008 OD, 1.5σ) plus curvature shoulders (minima of the second derivative of a 3 mm smooth) — inside physics-based windows: the disome 1.6–2.7 subunit steps after the 80S (ΔS from 80S to ~120S is twice the 60S→80S ΔS), each next n-mer at 0.4–0.9 of the previous spacing (spacings shrink with n). In each window the most prominent real peak wins; a shoulder counts only when no peak exists (dotted tick, letter “s” in the verdict). Valleys between assigned n-mers are minima of the segment after removing the line joining the two apexes, so they exist even on a rising hump. The consensus positions (medians over samples) label the chart as 2×, 3×, 4×, and the heavy boundary is auto-set at the 3|4 valley when 2-, 3- and 4-mer are assigned; A2/A3 in the extended table are the disome and trisome regions.

Verdict: resolved = 2-, 3- and 4-mer assigned; partial = disome only; unresolved = no candidate in the disome window. The halfmer (80S + 40S, ~100S) often appears as a shoulder ~7–10 mm after the 80S and is deliberately not assigned; it stays inside the monosome window that ends at g4.

Do not anchor at the valleys between polysome peaks for Poly/Mono. On an unresolved ladder the valleys are the polysome hump; connecting them subtracts the polysomes and leaves only ripples. Valley-to-valley baselines are for quantifying individual resolved peaks (the tool uses one for A40/A60, where the 40S and 60S are resolved).
Best: an empty gradient. Only a blank run under identical conditions can separate sucrose/refraction drift from the heavy-polysome rise at the tube bottom. One blank per session serves all runs of that session.

The dotted line in each trace's colour shows the baseline actually subtracted. A baseline error δ matters more than any integration detail: over a ~33 mm polysome window, 0.005 OD is ≈ 20 % of Apoly. Negative areas mean the baseline sits above the data — fix the model rather than dropping the sample. Nothing is clipped.

Boundary / baseline sensitivity

Mono / Poly is recomputed with the mono|poly boundary moved ±1–2 mm and the endpoint pulled back 4–16 mm, under two baseline models. A stable sample ranking means you are measuring the samples; a flip means you are measuring the setting — widen the window or report the min–max range beside the value. A model that produces negative areas is marked inadmissible.

Blocks, groups, contrasts

  • Block = one rotor/spin of one biological replicate; group = condition. Three rotors = n = 3, blocked.
  • Contrasts (A vs B; C vs D) are per-block differences of log2(Poly / Mono) between group means. With fewer than three blocks the summary is descriptive; from three blocks a paired t over blocks is shown. Never pool raw areas across blocks — they scale with loading and discard the blocking.
  • With the replicate scatter typical of these gradients, three rotors with one tube per condition detect only several-fold effects; plan duplicates per rotor or more rotors, and recompute after the first two.

Scale test

For every pair, one scalar c is fitted so that A ≈ c·B over the integration window (baseline-subtracted, aligned). Residual ≤ 10 % of A's RMS: the two differ by loading only; > 25 %: a real shape difference — a diagnostic that sends you to the lab notebook, not an exclusion criterion.

Lock settings

Freezes every analysis control and stamps a settings hash (boundaries, baseline, alignment, despiking, blank, contrasts, exclusions, QC thresholds) on the CSV, tidy CSV and Excel exports.

Input files

  • Single-trace instrument exports (BioComp Triax .csv) are the accurate source. Multi-sample “paste-up” CSVs put every sample on the first sample's position grid (0.1–0.5 mm off) — avoid them.
  • The duplicated readings around 0 mm are an instrument quirk (position reset at meniscus detection); the first-peak onset rule skips them.
  • Plain two-column position/OD files (.txt/.csv) are accepted too.
  • Scan date and time are read from the file header and shown next to each sample.

Display

“Fit y-axis” only zooms the display to the mono/poly regions; it never changes numbers. Hover the chart for the position and every sample's OD; drag on the background to zoom into an x-range, double-click to reset. Excluded samples stay on the chart, dimmed and dashed.

Session files

Save session writes a small JSON with boundaries, baseline, alignment, profile, blank, contrasts, lock state and every sample's block/group/A260/exclusion — no trace data. Load session restores it; load the same CSV files again and the metadata is re-applied by sample name. Share session copies a link carrying the same information in the URL fragment (compressed; the part after # never leaves the browser, so nothing is sent to any server) — a colleague who opens it and loads the same CSV files sees the identical analysis. The page also autosaves the current state in the browser and restores it on the next visit (a share link takes precedence); Clear all discards that autosave.
